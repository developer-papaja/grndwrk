What went wrong

The YAML header. Stories have a header with lists such as applies_to, and those were written in bracket form:

applies_to: [/clinic/visits, /clinic/visits/{visit}/book, app/Domain/Visits]

Inside [...], the characters { } [ ] , have special meaning in YAML. An unquoted item that contains one of them is invalid. Laravel routes always contain {visit}, {id} and so on, so every story whose applies_to listed a route with a parameter had a header strict parsers reject. js-yaml, PyYAML and Ruby's parser all fail on it. The fix is to quote each item:

applies_to: ["/clinic/visits", "/clinic/visits/{visit}/book", "app/Domain/Visits"]

Ten stories were affected.

Why it went unnoticed

1. The rules only warn about colons. The AGENTS.md rule says to quote a value when it contains ": ". It says nothing about { } [ ] ,, and CLAUDE.md says to fill applies_to with routes. So agents followed the rules and still wrote invalid YAML.
2. PHP's YAML parser accepts it. Symfony's parser, which the Laravel project has, reads it without complaint. When I first checked the stories with it, everything passed. Only a strict parser showed the error.
3. Grndwrk fails silently. When the header can't be read, the story shows only its id: no title, no status, no content. But the criteria counter reads the - [x] lines in the body, which still parse. So the card said "14 of 14 criteria met" while showing nothing else, and looked open.

A related problem: questions that didn't show

This was a format issue too, but no parser error was involved. A question appears as open only if it's a who: claude-asks entry in a thread. Questions written as checkboxes in a node's text ("Questions for a colleague: - [ ] …") never appeared. A plain who: claude note added later also closes every question above it. Nothing warns when either happens.

Suggestions for a long-term fix in grndwrk

1. Show parse errors instead of falling back to the id. For example: "The header couldn't be read: line 5, column 13".
2. Read the header and the criteria from the same parse, so a broken card doesn't also show "14 of 14 met".
3. Be lenient where it's safe. On a failed parse, try again with every list item quoted, and flag the card as needing repair.
4. Tighten the written rule in AGENTS.md and the commands: always quote list items in the header, or use a block list (- "/route/{id}"). Name { } [ ] , # & * ! explicitly, not just ": ".
5. Ship a check command that agents run after editing .grndwrk/, using the same parser as the app. It should also flag questions written as checkboxes, and claude notes that close open questions.
