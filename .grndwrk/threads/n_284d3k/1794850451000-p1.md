A plan for the shared store, nothing built yet.

**The idea that keeps it small:** the store keeps the same files, not a new schema. One row per file in `.grndwrk/` (project, path, content, version, who, when). Every command, the map's rules and the agent keep working on files, the format stays readable and diffable, and a project can move between the repo and the store and back. Tables for querying (views, the overview across apps, the API) are built from those files, as indexes.

**Steps, each usable on its own:**
1. **A seam in grndwrk.** Every read and write already goes through `src/store/fs.ts`. Behind it: the folder, or a store. Nothing else changes.
2. **The store, hosted by the team.** On Cloudflare like the relay (a Durable Object per project, D1 for the indexes, R2 for pictures), deployed with `grndwrk store deploy`, or a Postgres the team points to. One store holds many projects.
3. **Sync.** With a store, `.grndwrk/` is the agent's working copy: grndwrk fetches at start and when the store changes, and sends what the agent or the map wrote (the watcher sees it already). Each file has a version; since every new thing is a new file, two people rarely touch the same one. When they do, the newer change wins and the other is kept as a thread entry on the card, so nothing is lost.
4. **The page, with a login.** The map's own UI served by the store, for colleagues without the repo: read the map, answer questions (this is where n_kk4fxs lands), comment, add thoughts. Editing everything comes after.
5. **Across apps.** An overview of every project in the store (questions, gaps, focus, stories per app), thoughts searchable and linked across projects, and personas, segments and principles defined once and used by several.
6. **Views saved for everyone, and an API** (read only, with a key) for the team's own pages and reports.

**At init:** "Where is the map kept? In this repository (default), or in your team's store." `grndwrk store move` switches later, either way.

**The principle** "Lives in the project" becomes "Lives in the project by default": without a store, nothing changes.
