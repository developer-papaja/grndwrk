Taken from the answers: the team makes its own views on the shared data (filters, overviews, boards), saved for everyone, and builds its own pages or reports on top of the data outside grndwrk. A system without a repo can have its map only in the store, edited on the page, or in a repo made just for the map so an agent can work on it; both are fine.

So the store needs two things the files do not have today: views saved in the data for everyone (today the layout, grouping and filters are kept in each browser), and a documented way to read the data from outside (an API with a key, or an export), with the same shapes as the files so nothing is defined twice.
