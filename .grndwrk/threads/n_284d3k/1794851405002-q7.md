Is a protocol over HTTP custom enough, or should grndwrk also run a team's own adapter code?

Options:
- HTTP is enough: a team builds the store in any language and any host, and grndwrk only calls it
- Also an adapter: a small module in the team's repo that grndwrk loads to talk to their database directly (Firestore without a server, say). More custom, but grndwrk then runs code from the repository, which it avoids today because a pull request could change it
- HTTP now, and an adapter later if a team needs it
