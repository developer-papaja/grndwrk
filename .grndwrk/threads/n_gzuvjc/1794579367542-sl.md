Built as decided. A top screen can carry `part:` (Admin, Shop); the screens under it are in that part. When there is more than one part, the Sitemap view has a Part menu by the title, next to Variant: each part with how many screens it holds, or All parts, kept per project in this browser. Only the Sitemap is split; the map, the Inbox and Status stay whole. Opening a screen of another part (from the map, a link) draws that part. On a top screen, when the sitemap has more than one tree, the panel has a Part field to set it by hand; empty takes it out. `/sitemap` now looks for trees that share no parent and no link, asks once in the first top screen's thread whether to show them as sitemaps of their own, and writes `part:` only after a yes; after a no it does not ask again about those trees (src/shared/screens.ts, src/store/screens.ts, ui/src/state.ts, ui/index.html, commands/sitemap.md). Committed in 1fe2e1e.

To test:
1. Restart grndwrk once, so it reads `part:`, and run `npx grndwrk init` in a project to get the new /sitemap.
2. In a project with an admin side and a public side that do not connect, run /sitemap: it asks in the first top screen's thread whether to show them as two sitemaps.
3. Answer yes: the Sitemap view gets a Part menu with each part and All parts.
4. Pick one part: only its screens are drawn, and the summary under the title counts only those. The map, the Inbox and Status are unchanged.
5. Without /sitemap: open a top screen in the Sitemap, write a name in Part, press Enter; do the same with another top screen and another name. The Part menu appears.
6. Empty the Part field on one of them: the menu goes away when only one part is left.
