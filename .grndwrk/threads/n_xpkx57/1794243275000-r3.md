Done as you picked, both:
- The phone keeps a fingerprint of the round of fixing it is testing (grndwrk sends it with the status of a fix ready to test) and sends it back with Approve or Reject. grndwrk ignores a result for another round, so an old approval never settles a newer fix, even one built the same day (src/server/feedback.ts, Outbox.swift).
- Through the relay, grndwrk also ignores a result sealed before the fix's built date, which covers phones with an older version of the package (src/relay/sync.ts).
Tests cover both, and the phone code type-checks for the Simulator. The relay itself is unchanged. Committed in a0e5d95.

To test:
1. Rebuild the app with this version of the package, and restart grndwrk.
2. Comment from the phone, have a fix built, then on the phone Reject it.
3. Build the fix again (a new Claude entry with steps), then Approve it on the phone: it is marked fixed as usual.
