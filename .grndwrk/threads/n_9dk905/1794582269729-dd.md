The picture library reads font definitions only from the page's own stylesheets. A stylesheet from another server (Google Fonts, Bunny, a CDN) cannot be read that way, so its fonts were left out of the drawing, the text fell back to another font, and a wider fallback made lines overlap. The button now waits for the page's fonts, fetches such a stylesheet itself, keeps only the fonts the drawn part uses, and puts each font file into the drawing as data (at most a few MB). Tried with a page whose heading font comes from another local server: before, the picture showed a plain serif; now it shows the heading's own font (overlay/feedback.js, fontCss). Not committed yet.

To test:
1. Restart grndwrk once, so the button is the new one (a staging site needs grndwrk relay deploy again).
2. On a page whose fonts come from Google Fonts or another server, comment on a heading.
3. The comment's picture shows the heading in the page's own font, not overlapping the text below.
