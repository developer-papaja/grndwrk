Looked closer. None of the four is a problem for grndwrk.

- **yaml 2.9.1, `dist/nodes/Node.js`.** The flagged lines call a `reviver` or `onAnchor` function only when the caller passes one. grndwrk calls `parse(text, { prettyErrors: false, logLevel: 'error' })` and passes neither (`src/store/matter.ts`). Tried against hostile files: a `__proto__` key stays a plain key of that one object and changes nothing else; a file of nested aliases made to eat memory is refused ("Excessive alias count"); a `!!js/function` tag stays text. The file Socket flags is the library's normal code.
- **chokidar 5.0.0, environment.** It reads `CHOKIDAR_USEPOLLING` and `CHOKIDAR_INTERVAL`, nothing else, to choose between polling and native watching.
- **chokidar 5.0.0, filesystem.** Reads only, on the folder it is told to watch (`.grndwrk/`). It never writes.
- **grndwrk, URL strings.** Text inside the bundled DOMPurify, Alpine and marked. The page's Content-Security-Policy stops it from loading anything from another server.

Neither yaml, chokidar nor readdirp (chokidar's one dependency) opens a network connection or starts a program. `npm audit` finds no vulnerabilities, and `npm audit signatures` verifies the registry signatures and provenance of what is installed.
