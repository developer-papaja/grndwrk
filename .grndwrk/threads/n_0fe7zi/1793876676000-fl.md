My pick: a small relay grndwrk ships and you host yourself, for example a Cloudflare Worker on the free plan, set up with one command.

Why that one:

- **It goes both ways.** The phone does more than send: it shows which fixes are ready to test and sends Approve or Reject back. A relay can carry that, so colleagues on TestFlight get the same test flow you have on the Wi-Fi. A shared file cannot, and a GitHub repo can only clumsily.
- **No secret in the app.** For a GitHub repo or an S3 bucket, the TestFlight build would carry a key that writes there, and anyone with the build can dig it out. With a relay, each colleague gets their own key from an invite link or QR code you make in the map, the same kind of key a phone gets from pairing today, and you can take it away.
- **The relay sees nothing.** The phone can encrypt each comment with its key, so the relay only holds sealed boxes until your grndwrk fetches and opens them. It keeps nothing after that.
- **The map stays as it is.** Local, in git, the source of truth. The relay is opt in, and someone who never sets it up never sees it.

What it costs: a server exists, even a tiny one, which bends "no cloud". And it is the most work of the three: the Worker, invites in the map, the phone choosing between the Mac and the relay, fetching in grndwrk.

If that is too much for now, making the file share easier is a cheap first step (one tap on the phone, one drop on the map), but it stays one way: colleagues never see "ready to test".
