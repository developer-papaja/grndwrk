Built as you said: it asks. A phone that joined the relay and finds a grndwrk on the Wi-Fi that it is not paired with now asks once, "grndwrk is on this Wi-Fi": Keep using the relay, or Pair on the Wi-Fi. It no longer asks to be allowed a second time by itself. While it is not paired on the Wi-Fi, comments keep going through the relay, so nothing waits for `--lan` to be turned off. Keep using the relay is remembered for the project; long press, Pair with the Mac, still pairs. The long press says "on this Wi-Fi but not paired. Comments go through your team's relay meanwhile." Compiled for the Simulator; not tried on a phone yet.

To test:
1. Update the package in the app. On a phone that joined the relay and was allowed, start grndwrk with `--lan` on the same Wi-Fi, with the phone not paired on the Wi-Fi.
2. Open the app: it asks "grndwrk is on this Wi-Fi", with Keep using the relay and Pair on the Wi-Fi. The map shows no request to allow it.
3. Pick Keep using the relay and send a comment: it arrives in the map through the relay (`via: relay`) while `--lan` is still on.
4. Restart the app: it does not ask again.
5. Long press, Pair with the Mac: the map asks to allow it; once allowed, new comments come over the Wi-Fi (`via: lan`).
