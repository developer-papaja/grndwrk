The plan, from your answer:

- The relay serves the button's script (`/v1/<mailbox>/feedback.js`). The product adds the script tag only on staging, the way the local line sits inside `@env('local')` today.
- The address of the staging site is written into the mailbox when it is added (`grndwrk relay add --site https://staging.clinic.example`). The relay sends the script only to that site, and the script runs only there, so a tag left in production does nothing.
- Comments are sealed in the browser for the relay, as the phone does, and never go to anyone's Mac directly. The team's grndwrk fetches them as it does the phone's, with `via: relay` and the sender's name.
