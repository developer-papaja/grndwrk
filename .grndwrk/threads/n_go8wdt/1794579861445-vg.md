Built as decided, for comments; testing fixes from the staging site comes later. `grndwrk relay site https://staging…` names the site for the project's mailbox and prints the script line to add to the staging layout only. The relay serves the Comment button only to pages on that site, and the button runs only there, so a line left in production does nothing. On the staging site, Comment first asks for the invite (made in the map as for a phone), then shows four digits and waits; the map shows "A phone or browser joined with Tess's invite" with Allow. Comments written before that wait in the browser and go once allowed, with the picture, the colleague's name and the page's address. The browser never keeps the key itself, only keys made from it that cannot be read back out. The relay answers only that site, and only on what a phone may ask. Tried end to end on this Mac with a local relay and a stand-in staging page, and covered by tests (relay/src/relay.ts, overlay/relay.js, overlay/feedback.js, src/relay/sync.ts, src/relay/cli.ts). It needs a security review before it is released. Committed in 1fe2e1e.

To test:
1. Restart grndwrk in the project once, so it runs with the change.
2. In the project, run `grndwrk relay deploy` once, so your relay serves the button.
3. Run `grndwrk relay site https://<your staging address>` and add the line it prints to the staging site's layout, only for staging.
4. In the map, Sites (the globe), Colleagues: it names the staging site. Invite a colleague (or yourself) and copy the link.
5. Open the staging site, press Comment: it asks for the invite. Paste it and press Join: four digits show.
6. The map shows a banner with the same digits: Allow.
7. Comment on something on the staging site: it arrives on the Feedback page with the name from the invite and the page's address.
8. Open the production site (or any other) with the same line: no button, and the console says it only runs on the staging site.
